## Findings a future session would otherwise re-derive

**1. The extent rule (constraint 11).** `index_count × stride` **under-reads
57.7% of indexed draws** (2,427,176 of 4,207,622). A cache sized that way
uploads truncated buffers for most indexed geometry and renders subtly wrong.
The cache uses the **declared extent clamped to whole vertices** — the loosest
rule and the only one nothing has argued against. That is affordable, not merely
cautious: 51 MB/frame is bytes *referenced*, not uploaded; a persistent cache
uploads only on miss.

**Still unexplained:** 21% of indexed draws want more bytes under `count×stride`
than the fetch constant declares, 24% under the index range. A draw cannot read
past its own buffer, so stride, declared size, or their slot pairing is misread
for a fifth of draws. A ratio histogram is in place to separate a units error
(power-of-two spike) from a mapping error (scatter) — **it has never been run.**

**2. Constraint 9 was WRONG, and this changes the design (constraint 14).**
I had written that every translated vertex shader reads geometry through the
bindless stream heap. Counted over 406 translated vertex shaders by what their
HLSL declares:

    INPUT-LAYOUT semantics only   215      in float4 iPosition0 : POSITION0
    BOTH stream and semantics     105
    bindless NGPU_STREAM only      55
    neither                        31

Fable's corpus is close to the inverse (0 / 71 / 5 of 76). Same translator, same
`computed` flag deciding per fetch — so the split is a property of how each
**engine** indexes vertices. **BOTH is a real category, not a tie to break:**
such a shader needs an input layout *and* stream descriptors on the same draw.
The manifest must record what each shader **needs**, not which of two paths to
take. Interrogating DXIL per draw is not affordable.

**3. The stream binding arithmetic (constraint 13).**

    stream = 95 - (const_index * 3 + const_index_sel)      shader_recompiler.cpp:213
    NGPU_STREAM(s) -> g_VertexStreamHeap[g_StreamSlots[s >> 2][s & 3]]
    uint4 g_StreamSlots[4] : packoffset(c44)               // sixteen entries

Descriptors publish at index **95 − slot**, not slot. NG2 uses six fetch slots
(90..95) giving streams 0..5. `stream_range_check.py` gates indices outside the
array — **it does not catch a wrong index inside it**, which is exactly what the
inversion applied backwards produces: plausible geometry, not a failure. That
needs a frame compared against the plugin's own output.

**4. `vfetch_mini` carries neither its own `const_index` nor `stride`** (ucode.h:
"Applicable only to vfetch_full"). The runtime slot census read both from every
fetch instruction; fixed. 1,093 of 2,340 fetch instructions are minis (46.7%),
in 309 of 398 vertex programs.
**Do NOT apply that filter to the element table** — it is keyed by *instruction
address*, so every vfetch including minis needs an entry. Excluding them
reintroduces the refusal the rebuild exists to prevent. XenosRecomp already
carries the fields across minis itself (`if (!instr.isMiniFetch)`, :203), so the
translation was never exposed.

**5. The fetch constant has a TYPE field** (bits 0..1 of dword 0; kVertex = 3).
The census read past it for its entire life and used a plausibility heuristic in
its place. Now checked, with a per-type histogram — **never run**.

**6. The crash is deterministic per container ON NG2, and variable on Fable.**
Not a lottery here: 4 containers produce **nothing in 80 runs**, 2 controls
produce 20/20 with a single distinct output. Fable's four both crash and produce,
and every produced output is distinct (9/9, 8/8, 14/14, 12/12). Two behaviours,
one label — any explanation must account for both.
It is **not** the fetch lookup, from three directions: a dense table here moved
nothing, a refusing miss there moved nothing, and one NG2 crasher has *zero*
fetch instructions and never reaches the lookup. Zero vertex elements is a
precondition on both corpora and a cause on neither (343 of 411 NG2 vertex
containers declare zero; ~1 in 6 dies). **The difference is in the container, so
it is diffable** — that is the best position this defect has been in.
Killed offline: the CF-loop over-read hypothesis. All 625 NG2 and all 836 Fable
containers have code size ≡ 0 (mod 12), so that loop cannot walk past its buffer.

**7. The save-game path** (this cost five launches). `ng2_autoskip` hammers
A+Start for 25 s on every chapter load, which selects NEW GAME at the title
before the menu can be read — the build looks like it has no main menu. It has
six entries. **Set `skip_cinematics=0` first**; the launcher now refuses without
it. Saves live in `<exe>\user\<profile>\544307D5\00000001\`, NOT `<exe>\save\`,
and only 2 of 19 are imported; import is via the Settings screen
(`ng2_saveimport.h`: STFS extract, then move from content type 00000002/XUID 0
to the profile's 00000001). Working path with auto-skip off:
START, START → title → START → menu → DOWN, A (LOAD GAME) → LEFT
(WARRIOR | MASTER NINJA | ACOLYTE) → A → costume select → A → chapter card → A.

## Built but NOT verified

**The guest vertex stream cache.** Keyed `(base, stride, endian)` — not size.
One 256 MB persistent buffer with a bump allocator, two-phase (WantStream on the
draw thread is a map probe and a push; BuildPendingStreams on the render thread
reads guest memory, swaps endian, uploads, re-arms the write-watch). Anti-thrash
at 4 invalidations → 600-frame bypass. Gated behind `NG2_NATIVE_GPU_STREAMS`,
default off, **and nothing binds it**.

It compiles. It has never run. The endian swap is verified *by derivation*
against the engine's `GpuSwap` for all three modes; the bump allocator is not
verified at all.

Three silent-failure modes handled deliberately, worth preserving in any rewrite:
the build records `copyBufferRegion` so it must sit **inside** the command list
(before `begin()` the copies vanish with no error and every counter still reads
healthy); the write-watch is re-armed on **every** build and rebuild
(`GetWriteWatch` consumes what it reports, so a missed re-arm serves stale
geometry forever with a *better*-looking hit rate); a failed watch query counts
as **dirty**, not clean.

It is **incomplete, not wrong** — the right structure for the 160 shaders that
read streams, and useless to the 215 that need an input layout.

`crash_census.py`, `refusal_audit.sh`, `determinism_census.py`, `run_capped.py`,

**The one habit that produced most of tonight's findings:** check a decoder
against the **compiled artefact**, not against documentation or another decoder.
Two decoders of the same format, written from the same docs, fail the same way.
The generated HLSL exposed a broken census of mine, confirmed the six fetch
slots, and refuted constraint 9. And: *over-reading is silent, under-reading is
loud* — a parser that stops early says "unparseable"; one that runs past the end
reports more data and looks like success.
